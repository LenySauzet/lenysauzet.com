# Languages

English at `/`, French at `/fr`, on next-intl over Next 16's own pieces: an
`app/[locale]` root and `next/root-params`. The blog and the project titles stay in
English (`CONTENT_LOCALE`).

## Routing

- **No proxy.** `next.config.ts` redirects `/en/*` to `/*` for good and rewrites every
  other unprefixed path to `/en/*` (`beforeFiles`), skipping `/fr`, `_next`, files and
  the share image. The rewrites chain, so `/en` is excluded from the second one. A
  visitor is never sent elsewhere than they asked: no `Accept-Language`, no cookie.
- **Every route is under `app/[locale]`**, static per language, with
  `dynamicParams = false` so a segment that is no language reaches `global-not-found`;
  `[...rest]` keeps its params dynamic, so `/fr/x` gets the French 404.
- **`next/root-params` gives the locale** to `i18n/request.ts`. Its types are
  generated, so `type-check` runs `next typegen` first. Route handlers cannot read it:
  `/resume` takes its `params`.
- **Paths and URLs come from `i18n/locales.ts`**: `homePath`, `homeUrl`,
  `homeAlternates` (with `x-default`), `otherVersionOf`. They go through `getPathname`,
  which leaves the default language unprefixed; next-intl's `Link` and router would
  force `/en`.

## Messages

- **`messages/en.json` is the type** (`i18n/app-config.d.ts`); `i18n/messages.test.ts`
  holds French to the same keys, arguments and tags, and to French typography: a narrow
  no-break space before `? ! ;`, a no-break space before `:`, `’`, `…`.
- **French is an edition, not a translation**: written in French, tool names in English.
- **Server components use `useTranslations`**, or `getTranslations` when async; client
  ones get every message from `NextIntlClientProvider`. Code outside React (the
  commands, the services) receives its sentences and never imports a translator.
- **Dates and times follow the page**: `useFormatter` and `Intl` with the locale, the
  time zone set once in the request config.

## Between the two

- **Switching loads the page** (`useOtherVersion`, the footer's plain link): a client
  navigation would remount the `[locale]` root and next-themes' script with it, which
  React refuses to render on the client.
- **Each page names the other in its own language**: "French version", "Read in
  French", "French version available".
- **`OtherVersion` (home page only) offers it once a visit** (`sessionStorage`) to a
  visitor whose first browser language is the other one. It listens to the island and
  presents its announcement in the same tick the hint leaves, so the name never shows
  in between; not if the visitor reached for the island, and a hidden tab waits to be
  seen. The island holds an announcement while pointed at, and a click runs it.
- **The palette's search ignores accents** (`lib/commands/search.ts`).
- **Each language has its resume** (`siteConfig.resumes`) and its presence room
  (`.claude/rules/presence.md`).
